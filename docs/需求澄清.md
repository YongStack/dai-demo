## 1. 一句话概述

从零搭建一个网球产品在线购物网站（前端 React/Next.js + 后端 Node.js/NestJS + PostgreSQL，Docker 容器化部署），使消费者能够在线浏览、搜索、下单和支付网球相关商品（球拍、球鞋、服装、球包、护具、配件等六大品类），获得完整的电商购物闭环体验，同时不涉及线下门店、供应链管理、ERP 系统集成及售后退换货流程。

## 2. 背景与目标

### 背景
- 当前无任何现有线上渠道，用户无法通过互联网浏览和购买网球相关商品。
- 网球运动覆盖球拍、球鞋、服装、用球、球包、护具、配件等多品类，需要一个面向 C 端消费者的标准电商网站。
- 本次需求触发来源：业务推进——需要建立线上销售渠道。

### 目标
- 消费者可在线浏览网球商品目录，按分类和关键词搜索商品。
- 消费者可将商品加入购物车并完成下单支付（支付宝/微信支付），获得完整购物闭环。
- 系统提供商品管理、订单管理基础后台能力，支撑日常运营。
- 用户可通过手机号注册登录管理个人信息和订单历史。

### 不做
- 不做线下门店导购或 O2O 模式。
- 不做供应链管理、仓储 WMS、物流 TMS 系统集成。
- 不做 ERP/财务系统对接。
- 不做移动端原生 App（本轮聚焦 Web 网站，响应式适配移动端浏览）。
- 不做会员积分体系和复杂营销玩法（优惠券、拼团、秒杀等）。
- 不做跨境支付和多币种结算。
- 不做售后退换货流程（退款、退货、换货均不在本轮范围）。

## 3. 需求详情

### 用户场景

| 用户/角色 | 使用场景 | 期望结果 |
|-----------|----------|----------|
| C 端消费者（已注册） | 浏览网球商品、搜索、加入购物车、下单支付 | 完成购买，查看订单状态 |
| C 端消费者（未注册访客） | 浏览商品、搜索 | 可浏览，下单时引导注册/登录 |
| 管理员/运营人员 | 管理商品上下架、查看和处理订单 | 维护商品目录，处理订单流转 |

### 用户路径（C 端消费者主流程）

1. 用户访问网站首页，查看推荐商品和分类入口。
2. 用户通过分类导航或搜索框查找目标网球商品。
3. 用户进入商品详情页，查看商品图片、价格、规格、库存和描述。
4. 用户选择规格（如球拍磅数、尺码等），加入购物车。
5. 用户在购物车页确认商品和数量，点击去结算。
6. 用户填写/选择收货地址，确认订单信息（含运费计算）。
7. 用户选择支付方式（支付宝或微信支付）并完成支付。
8. 支付成功后，用户看到订单确认页，可在"我的订单"中查看订单状态。

### 异常路径
- 搜索无结果：展示空态页面，推荐热门商品或热门搜索词。
- 商品缺货：商品详情页显示"暂时缺货"，不可加入购物车。
- 支付失败：提示支付失败原因，保留订单，引导用户重新支付。
- 库存不足（下单时）：提示库存不足，引导用户调整数量。
- 支付超时：订单创建后 30 分钟内未完成支付，系统自动取消订单并释放库存，提示用户"订单支付超时，请重新下单"。

### 产品规则

#### 商品展示规则
- 首页展示推荐商品轮播和分类入口（六大品类：网球拍、网球/网球包、网球鞋、网球服装、球包/护具、配件）。
- 商品列表页支持按分类筛选、价格排序（升序/降序）、按销量排序。
- 每个商品卡片展示：商品主图、名称、价格、销量、上架状态。
- 商品详情页展示：多图轮播、名称、价格、规格选项、库存状态、商品描述。

#### 商品分类规则
- 一级分类为六大品类：网球拍、网球/网球包、网球鞋、网球服装、球包/护具、配件。
- 管理员可在后台管理分类（新增、编辑、删除）。
- 每个商品必须归属一个一级分类。

#### 购物车规则
- 用户加入购物车后，购物车数量角标实时更新。
- 购物车内可修改商品数量、删除商品、勾选/取消勾选商品。
- 未登录用户可加入购物车，下单时需先登录。
- 同一商品不同规格视为购物车中不同条目。

#### 下单规则
- 下单前必须登录/注册。
- 一笔订单可包含多个商品条目。
- 下单时需选择收货地址，支持新增和切换地址。
- 订单金额 = 商品金额 + 运费。
- 运费规则：订单商品金额满 99 元免运费，未满 99 元收取 10 元运费。
- 下单后预扣库存，支付成功后实扣库存；订单取消后释放预扣库存。

#### 支付规则
- 支持的支付方式：支付宝、微信支付。
- 支付超时时间：订单创建后 30 分钟内未完成支付，自动取消订单并释放库存。
- 支付成功后订单状态变为"待发货"。
- 支付流程保证幂等性，避免重复扣款。

#### 订单状态流转
- 待支付 → 待发货 → 待收货 → 已完成
- 待支付状态可由用户主动取消，也可因支付超时自动取消。
- 待发货状态由管理员操作发货后变为待收货。
- 待收货状态由用户确认收货后变为已完成。
- 已完成状态为终态，本轮不含售后流程，不支持退款/退货/换货。

#### 用户账户规则
- 支持手机号 + 短信验证码方式注册和登录。
- 用户可管理收货地址（新增、编辑、删除、设为默认）。
- 用户可查看订单列表和订单详情。
- 用户可查看和编辑个人基本信息（昵称、手机号等）。

#### 后台管理规则
- 管理员需通过独立后台入口登录，具备独立权限控制。
- 管理员可新增、编辑、上下架商品（含名称、价格、图片、描述、库存、分类、规格）。
- 管理员可查看订单列表，修改订单状态（发货操作）。
- 管理员可管理商品分类（新增、编辑、删除）。

### 状态与反馈
- **成功**：加购成功显示"已加入购物车"提示；下单成功跳转订单确认页；支付成功显示支付成功页。
- **失败**：加购失败（缺货等）显示具体原因；支付失败显示失败原因并保留订单，引导重新支付。
- **空态**：搜索无结果时展示空态页并推荐热门商品；购物车为空时提示"购物车空空如也，去逛逛吧"并引导去逛逛；订单列表为空时提示"暂无订单"。
- **无权限**：未登录用户点击去结算/查看订单时跳转登录页，登录后返回原页面；非管理员访问后台入口时拒绝访问。
- **异常**：网络异常显示"网络异常，请稍后重试"并保留用户操作状态；支付超时自动取消订单并提示用户重新下单。
- **保持不变**：无（全新项目，无既有行为需保持）。

### 关键文案
- 首页 Slogan："你的网球装备，一站搞定"
- 加入购物车按钮："加入购物车"
- 立即购买按钮："立即购买"
- 缺货提示："该商品暂时缺货"
- 搜索空态："没有找到相关商品，看看这些热门推荐"
- 购物车空态："购物车空空如也，去逛逛吧"
- 订单空态："暂无订单"
- 支付超时："订单支付超时，请重新下单"
- 运费提示："满 99 元免运费，还差 ¥X 元"
- 运费已免："已满 99 元，免运费"

### 关键表现要求
- 网站需响应式适配 PC 和移动端浏览器。
- 商品图片需支持懒加载，保障首屏加载速度。
- 购物车角标数量更新需实时响应，无明显延迟。
- 支付流程需保持流畅，支付结果回调后页面跳转不超过 3 秒。

## 4. 约束限制

- **权限要求**：C 端用户需手机号注册登录后方可下单和管理订单；管理员需独立后台登录入口和权限控制。
- **兼容要求**：支持主流浏览器（Chrome、Safari、Edge、Firefox 最新版本）；移动端响应式适配。
- **性能要求**：首页首屏加载 ≤ 3 秒；商品列表分页加载，每页默认 20 条；搜索响应 ≤ 1 秒。
- **稳定性要求**：支付流程需保证幂等性，避免重复扣款；订单状态变更需保证数据一致性；支付超时自动取消需可靠执行。
- **技术栈**：前端 React / Next.js；后端 Node.js + NestJS；数据库 PostgreSQL。
- **部署方式**：Docker 容器化部署。
- **实现边界**：本轮为全栈 Web 应用，前端 + 后端 + 数据库，不含移动 App 和小程序。

## 5. 验收标准

- [主流程] 在网站已上架商品的前提下，用户从首页进入 → 浏览/搜索商品 → 进入详情页 → 选择规格加入购物车 → 购物车确认 → 填写地址 → 选择支付宝或微信支付 → 支付成功，系统应展示订单确认页且"我的订单"中出现该笔订单，订单状态为"待发货"。
- [搜索] 在商品列表页输入关键词搜索，系统应返回名称匹配的商品列表；无匹配结果时展示空态页和热门推荐。
- [未登录拦截] 未登录用户点击"去结算"时，系统应跳转登录页，登录成功后返回结算页。
- [库存约束] 当商品库存为 0 时，详情页应显示"暂时缺货"且"加入购物车"按钮不可点击。
- [运费计算] 当订单商品金额 < 99 元时，订单总金额应包含 10 元运费；当订单商品金额 ≥ 99 元时，订单免运费。
- [订单状态流转] 支付成功后订单状态应变为"待发货"；管理员发货后状态变为"待收货"；用户确认收货后状态变为"已完成"。
- [支付超时] 订单创建后 30 分钟内未支付，系统应自动取消订单并释放预扣库存。
- [支付幂等] 同一笔订单重复发起支付请求时，系统应保证只扣款一次，不产生重复扣款。
- [后台管理] 管理员登录后台后，可新增商品（含名称、价格、图片、描述、库存、分类、规格），商品在前台可见；可下架商品，前台不可见。
- [分类管理] 管理员可在后台管理六大品类分类，新增/编辑/删除分类后前台分类导航同步更新。
- [兼容稳定] 网站在 Chrome、Safari、Edge、Firefox 最新版本及移动端浏览器中均可正常浏览和操作。
