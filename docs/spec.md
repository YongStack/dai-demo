# Spec: 网球产品在线购物网站

## 1. Context

- **需求来源**：业务推进——当前无任何线上渠道，需要建立面向 C 端消费者的网球产品在线销售渠道。
- **商业背景**：网球运动覆盖球拍、球鞋、服装、用球、球包、护具、配件等多品类，需要一个标准电商网站承载线上销售。
- **用户角色与核心痛点**：
  - C 端消费者（已注册/未注册访客）：无法通过互联网浏览和购买网球相关商品。
  - 管理员/运营人员：无法在线管理商品目录和处理订单。
- **技术栈约束**：前端 React/Next.js + 后端 Node.js/NestJS + PostgreSQL，Docker 容器化部署。
- **项目状态**：全新项目，仓库当前仅含 README 和需求澄清文档，无既有代码。

## 2. Goals and Non-Goals

### Goals

| 目标 | 衡量方式 | 目标值 / 判断标准 |
|------|----------|-------------------|
| 消费者可在线浏览和搜索网球商品 | 首页加载、商品列表、搜索功能可用 | 首页首屏加载 ≤ 3 秒；搜索响应 ≤ 1 秒 |
| 消费者可完成加购→下单→支付的完整购物闭环 | 主流程端到端可走通 | 支付成功后订单状态为"待发货" |
| 系统提供商品/订单管理后台能力 | 管理员可管理商品和订单 | 商品上下架前台实时反映；订单状态可流转 |
| 用户可注册登录管理个人信息和订单 | 手机号注册登录流程可用 | 注册→登录→查看订单链路完整 |

### Non-Goals

- 不做线下门店导购或 O2O 模式
- 不做供应链管理、仓储 WMS、物流 TMS 系统集成
- 不做 ERP/财务系统对接
- 不做移动端原生 App（仅 Web 网站响应式适配移动端）
- 不做会员积分体系和复杂营销玩法（优惠券、拼团、秒杀等）
- 不做跨境支付和多币种结算
- 不做售后退换货流程（退款、退货、换货均不在本轮范围）

## 3. Glossary

| 术语 | 定义 |
|------|------|
| SKU | Stock Keeping Unit，商品最小存货单元；同一商品不同规格对应不同 SKU |
| 预扣库存 | 下单时锁定库存，支付成功后转为实扣，订单取消时释放 |
| 支付幂等 | 同一笔订单重复发起支付请求时，系统保证只扣款一次 |
| 六大品类 | 网球拍、网球/网球包、网球鞋、网球服装、球包/护具、配件 |
| 待支付→待发货→待收货→已完成 | 订单状态机的四种核心状态 |

## 4. Functional Requirements

### REQ-001: 商品浏览与展示

- **User Story**: As a 消费者, I want 浏览网球商品目录并查看商品详情, so that 我能了解商品信息并决定购买。
- **Priority**: P0
- **Description**: 系统首页展示推荐商品轮播和六大品类分类入口；商品列表页支持按分类筛选、价格排序（升序/降序）、按销量排序，分页展示，每页默认 20 条；商品卡片展示主图、名称、价格、销量；商品详情页展示多图轮播、名称、价格、规格选项、库存状态和商品描述。

Acceptance Requirements (EARS):
- REQ-001.1: The system shall 在首页展示推荐商品轮播和六大品类分类入口。
- REQ-001.2: The system shall 在商品列表页支持按分类筛选、价格升序/降序排序、按销量排序。
- REQ-001.3: The system shall 在商品列表页分页展示商品，每页默认 20 条。
- REQ-001.4: When 商品库存为 0 时, the system shall 在商品详情页显示"该商品暂时缺货"且"加入购物车"按钮不可点击。
- REQ-001.5: The system shall 在商品卡片展示主图、名称、价格、销量。

```gherkin
Scenario: 消费者浏览商品详情
  Given 网站已上架库存大于 0 的网球拍商品
  When 消费者进入该商品详情页
  Then 消费者看到商品多图轮播、名称、价格、规格选项、库存状态和商品描述
  And "加入购物车"按钮可点击
```

### REQ-002: 商品搜索

- **User Story**: As a 消费者, I want 通过关键词搜索网球商品, so that 我能快速找到目标商品。
- **Priority**: P0
- **Description**: 用户在搜索框输入关键词后，系统返回名称匹配的商品列表，搜索响应 ≤ 1 秒。

Acceptance Requirements (EARS):
- REQ-002.1: The system shall 根据用户输入的关键词返回名称匹配的商品列表。
- REQ-002.2: When 搜索无匹配结果时, the system shall 展示空态页并推荐热门商品。
- REQ-002.3: The system shall 在搜索响应 ≤ 1 秒内返回结果。

```gherkin
Scenario: 搜索无结果
  Given 网站已上架商品
  When 消费者搜索一个不存在的关键词
  Then 系统展示空态页"没有找到相关商品，看看这些热门推荐"
  And 页面展示热门推荐商品
```

### REQ-003: 购物车

- **User Story**: As a 消费者, I want 将商品加入购物车并管理购物车, so that 我能汇总要购买的商品并调整数量。
- **Priority**: P0
- **Description**: 用户在商品详情页选择规格后可加入购物车或立即购买；购物车支持修改数量、删除商品、勾选/取消勾选；同一商品不同规格视为不同条目；未登录用户可加购，下单时引导登录。

Acceptance Requirements (EARS):
- REQ-003.1: The system shall 在用户加入购物车后实时更新购物车数量角标。
- REQ-003.2: The system shall 将同一商品不同规格作为购物车中的不同条目处理。
- REQ-003.3: The system shall 允许未登录用户加入购物车。
- REQ-003.4: When 购物车为空时, the system shall 展示"购物车空空如也，去逛逛吧"并引导用户去逛逛。

```gherkin
Scenario: 未登录用户加入购物车
  Given 消费者未登录且商品库存充足
  When 消费者选择规格并点击"加入购物车"
  Then 系统显示"已加入购物车"提示
  And 购物车角标数量更新
```

### REQ-004: 下单与结算

- **User Story**: As a 已注册消费者, I want 选择收货地址、确认订单信息并提交订单, so that 我能完成下单操作。
- **Priority**: P0
- **Description**: 用户在购物车确认商品后点击"去结算"，需登录后进入结算页；结算页需选择/新增收货地址、确认商品和运费；订单金额 = 商品金额 + 运费；满 99 元免运费，未满 99 元收 10 元运费；下单后预扣库存。

Acceptance Requirements (EARS):
- REQ-004.1: When 未登录用户点击"去结算"时, the system shall 跳转登录页，登录成功后返回结算页。
- REQ-004.2: The system shall 计算订单金额 = 商品金额 + 运费。
- REQ-004.3: When 订单商品金额 ≥ 99 元时, the system shall 免收运费。
- REQ-004.4: When 订单商品金额 < 99 元时, the system shall 收取 10 元运费。
- REQ-004.5: The system shall 在下单后预扣库存。
- REQ-004.6: When 下单时库存不足, the system shall 提示库存不足并引导用户调整数量。
- REQ-004.7: When 订单创建成功时, the system shall 跳转支付选择页。

```gherkin
Scenario: 运费计算 - 满 99 元免运费
  Given 消费者已在购物车选中商品金额合计 120 元
  When 消费者点击"去结算"并确认订单
  Then 订单总金额为 120 元（免运费）
  And 页面显示"已满 99 元，免运费"

Scenario: 运费计算 - 未满 99 元收运费
  Given 消费者已在购物车选中商品金额合计 80 元
  When 消费者点击"去结算"并确认订单
  Then 订单总金额为 90 元（含 10 元运费）
  And 页面显示"满 99 元免运费，还差 ¥19 元"
```

### REQ-005: 支付

- **User Story**: As a 已注册消费者, I want 选择支付宝或微信支付完成付款, so that 我能完成购买。
- **Priority**: P0
- **Description**: 用户在订单创建后选择支付宝或微信支付完成支付；支付成功后订单状态变为"待发货"；支付流程保证幂等性；订单创建后 30 分钟内未支付自动取消并释放库存。

Acceptance Requirements (EARS):
- REQ-005.1: The system shall 支持支付宝和微信支付两种支付方式。
- REQ-005.2: When 支付成功时, the system shall 将订单状态变为"待发货"并展示支付成功页。
- REQ-005.3: The system shall 保证支付流程幂等性，同一笔订单重复发起支付请求时只扣款一次。
- REQ-005.4: When 订单创建后 30 分钟内未完成支付时, the system shall 自动取消订单并释放预扣库存。
- REQ-005.5: When 支付失败时, the system shall 提示失败原因并保留订单，引导用户重新支付。
- REQ-005.6: When 支付超时自动取消订单时, the system shall 提示用户"订单支付超时，请重新下单"。

```gherkin
Scenario: 支付成功
  Given 消费者已创建订单且订单状态为"待支付"
  When 消费者选择支付宝并完成支付
  Then 订单状态变为"待发货"
  And 系统展示支付成功页
  And "我的订单"中出现该笔订单

Scenario: 支付超时自动取消
  Given 消费者已创建订单且 30 分钟内未支付
  When 系统定时检查到该订单超时
  Then 系统自动取消订单
  And 释放预扣库存
  And 提示用户"订单支付超时，请重新下单"
```

### REQ-006: 订单管理

- **User Story**: As a 消费者, I want 查看我的订单列表和详情, so that 我能跟踪订单状态。
- **Priority**: P0
- **Description**: 用户可在"我的订单"页查看订单列表和详情；订单状态流转为：待支付→待发货→待收货→已完成；待支付状态可由用户主动取消或因超时自动取消；待收货状态由用户确认收货后变为已完成。

Acceptance Requirements (EARS):
- REQ-006.1: The system shall 允许用户查看订单列表和订单详情。
- REQ-006.2: When 用户在"待收货"状态点击确认收货时, the system shall 将订单状态变为"已完成"。
- REQ-006.3: When 用户在"待支付"状态主动取消订单时, the system shall 取消订单并释放预扣库存。
- REQ-006.4: When 订单列表为空时, the system shall 展示"暂无订单"空态。

```gherkin
Scenario: 订单状态完整流转
  Given 订单已创建，状态为"待支付"
  When 消费者支付成功
  Then 状态变为"待发货"
  When 管理员操作发货
  Then 状态变为"待收货"
  When 消费者确认收货
  Then 状态变为"已完成"
```

### REQ-007: 用户注册登录与账户管理

- **User Story**: As a 消费者, I want 通过手机号注册登录并管理个人信息和收货地址, so that 我能下单和管理我的账户。

- **Description**: 支持手机号+短信验证码注册和登录；用户可管理收货地址（新增、编辑、删除、设为默认）；用户可查看和编辑个人基本信息（昵称、手机号等）；用户可查看订单历史。

Acceptance Requirements (EARS):
- REQ-007.1: The system shall 支持手机号 + 短信验证码方式注册和登录。
- REQ-007.2: The system shall 允许用户管理收货地址（新增、编辑、删除、设为默认）。
- REQ-007.3: The system shall 允许用户查看和编辑个人基本信息（昵称、手机号等）。
- REQ-007.4: The system shall 允许用户查看订单列表和订单详情。

```gherkin
Scenario: 手机号注册登录
  Given 消费者访问网站且未登录
  When 消费者输入手机号并获取短信验证码

```

### REQ-008: 后台管理 - 商品管理

- **User Story**: As a 管理员, I want 管理商品上下架和分类, so that 我能维护商品目录并控制前台展示。
- **Priority**: P0
- **Description**: 管理员通过独立后台入口登录；可新增、编辑、上下架商品（含名称、价格、图片、描述、库存、分类、规格）；可管理商品分类（新增、编辑、删除）；每个商品必须归属一个一级分类。

Acceptance Requirements (EARS):
- REQ-008.1: The system shall 提供独立后台入口供管理员登录，具备独立权限控制。
- REQ-008.2: The system shall 允许管理员新增商品（含名称、价格、图片、描述、库存、分类、规格），上架后商品在前台可见。
- REQ-008.3: The system shall 允许管理员下架商品，下架后前台不可见。
- REQ-008.4: The system shall 允许管理员管理六大品类分类（新增、编辑、删除），变更后前台分类导航同步更新。
- REQ-008.5: When 非管理员访问后台入口时, the system shall 拒绝访问。
- REQ-008.6: The system shall 要求每个商品归属一个一级分类。

```gherkin
Scenario: 管理员新增商品并上架
  Given 管理员已登录后台
  When 管理员填写商品信息（名称、价格、图片、描述、库存、分类、规格）并提交

  And 前台可浏览到该商品
```

Scenario: 管理员发货

## 5. UX Design

### 体验目标与设计原则

- 购物流程简洁高效，从浏览到支付的核心路径步骤不超过 8 步。
- 响应式适配 PC 和移动端浏览器，移动端优先触控交互。
- 商品图片支持懒加载保障首屏加载速度。
- 购物车角标数量实时更新，无明显延迟。
- 支付结果回调后页面跳转不超过 3 秒。

### 页面 / 模块 / 入口范围

| 页面 | 入口 | 核心功能 |
|------|------|----------|
| 首页 | 网站根路径 | 推荐商品轮播、六大品类分类入口、搜索框 |
| 商品列表页 | 首页分类入口/搜索结果 | 分类筛选、价格/销量排序、分页浏览 |
| 商品详情页 | 商品卡片点击 | 多图轮播、规格选择、库存状态、加购/立即购买 |
| 购物车页 | 顶部购物车图标 | 商品列表、数量调整、勾选/删除、去结算 |

## 6. Backend/Data

### 商品数据模型

- **商品（Product）**：名称、价格、描述、分类（外键）、图片列表、销量、上架状态。
- **商品规格（SKU）**：所属商品（外键）、规格属性（如磅数、尺码）、库存数量、SKU 编码。
- **分类（Category）**：分类名称、排序、创建时间。
- 每个商品必须归属一个一级分类。

### 订单数据模型

- **订单（Order）**：订单号、用户（外键）、订单状态、商品总金额、运费、订单总金额、收货地址、支付方式、创建时间、支付时间。
- **订单明细（OrderItem）**：订单（外键）、商品（外键）、SKU（外键）、购买数量、单价快照。
- **收货地址（Address）**：用户（外键）、收货人、手机号、详细地址、是否默认。

### 库存规则

- 下单时预扣库存（锁定）。
- 支付成功后实扣库存（扣减）。
- 订单取消（用户主动/支付超时）后释放预扣库存。
- 库存数量变更需保证数据一致性（并发场景下避免超卖）。

### 订单状态机

| 操作 | 前置状态 | 目标状态 |
|------|----------|----------|
| 创建订单 | — | 待支付 |
| 支付成功 | 待支付 | 待发货 |
| 用户主动取消 | 待支付 | 已取消 |
| 支付超时自动取消 | 待支付 | 已取消 |
| 管理员发货 | 待发货 | 待收货 |
| 用户确认收货 | 待收货 | 已完成 |

### 支付幂等性

- 支付请求携带订单号作为幂等键。
- 系统在处理支付回调时检查订单支付状态：已支付的订单不重复扣款。
- 支付超时定时任务与支付回调可能并发，需保证状态变更原子性。

### 支付超时机制

- 订单创建后 30 分钟内未完成支付，定时任务自动取消订单并释放预扣库存。
- 定时任务需可靠执行，避免漏取消或重复取消。

### 权限模型

- C 端用户：手机号注册登录，可浏览、加购、下单、支付、管理个人信息和订单。
- 管理员：独立后台入口登录，独立权限控制，可管理商品、分类、订单。
- 未登录用户：可浏览和搜索商品，可加购，下单时引导登录。

### 支付集成

- 对接支付宝和微信支付（具体 API 对接细节属于实现层面，不在 Spec 范围）。
- 支付沙箱/正式环境配置：待确认（见 Open Questions）。
